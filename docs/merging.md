# 节目合并规则

my-epg 以播放列表确定输出频道，再从多个 XMLTV 源匹配节目。频道覆盖、节目窗口和备用源分别解决不同问题。

## 源组与优先级

一个源组包含主站和镜像。脚本依次尝试，采用第一个成功下载并解析的源。不同源组都参与后续合并，`priority` 越小越优先。

同一频道的节目按时段处理：高优先级源先占用时间区间，低优先级源只补未覆盖的片段。这样可用 epg.pw 的较长时间范围补齐当天源之后的节目，同时减少重叠节目。

默认组按老张 EPG、112114、epg.pw、kuke31、CCSH 的顺序安排优先级。源规模和可提供的天数随上游变化，不作为固定覆盖保证。

## 频道与时间窗口

播放列表中不同名称可共享一个输出 ID，例如 4K 与高清版本。没有节目数据的 ID 仍有 `channel` 节点，播放器通常显示暂无节目。

默认时间窗口从北京时间当天零点开始，向后取 7 天。配置 `--days` 调整输出窗口，只能筛选上游已有节目，不能生成上游未提供的未来数据。

脚本还会清理文本、排除无效时间，并将异常长节目限制在 8 小时内。这些规则用于处理源数据，不对电视台实际播出时间作保证。

## 覆盖的含义

播放列表频道数、输出 ID 数和有节目的 ID 数不是同一个统计。多个播放流可共用 ID；一个有效 ID 也可能暂时没有节目。实时结果应查看构建报告，而不是在 README 中固定一组数量。
